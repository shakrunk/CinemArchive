## Current audit — 2026-10-14

The status column is reconciled against [Full mobile and web parity](full-parity-execution.md), whose original capability inventory and dated executable evidence govern this effort. Older implementation-status prose in linked contracts is historical; their API and authorization requirements remain relevant. Current source and tests take precedence over prose.

Implementation and available-environment acceptance are verified, including the unowned recommendation Add fallback. Full device acceptance is not claimed. Native and web post-show routing and native blocked-friend refresh passed the final rendered checks. Firefox service-worker offline shell and lazy navigation pass against a disconnected origin. The user has no Safari device, so real Safari offline navigation remains explicitly unverified; automated WebKit coverage is not a substitute. Recent native live journeys used the API-36 emulator, not a physical handset. See the [closing acceptance checklist](full-parity-execution.md#closing-acceptance-checklist-reconciled-2026-10-13) and subsequent evidence.

## Contract completion rules

Every row must document the following before its first Android write is enabled:

1. Request and response fields, IDs, enum values, timestamps, pagination, and error codes.
2. The RLS authorization matrix, including the unauthorized direct-REST case.
3. Whether the action is idempotent, its operation ID format, and retry/conflict behavior.
4. JSON fixture files derived from production-compatible test data and a test that runs them on both web and Android logic where applicable.
5. An Android route and its loading, empty, offline, and recoverable-error states.
