## Scope boundaries

Unimplemented ideas on both clients (for example account deletion, joint-outing polls, and general backlog enhancements) are not existing parity gaps. They remain separate backlog work unless required to complete a shipped behavior. No public release or production deployment is implied by local implementation.

Current web JSON export includes title graphs and outings. It excludes lists and embedded ticket-photo bytes; import skips existing `(tmdbId,type)` titles and their outings instead of merging histories, and admits one complete title graph per durable command. Native parity must preserve that exported graph and report the same duplicate/partial-admission outcomes. Whole-backup photo bundles, list inclusion and duplicate-history merging are separate enhancements absent from both existing flows; this does not waive per-ticket original export or ordinary list parity.

Material You colors, APK updating, OS permission UI, predictive back, exact alarm APIs, and brightness controls have platform-specific implementations. Equivalent user outcomes still require review: e.g. a due outing must converge consistently, and ticket content must remain usable. Typography accessibility is a user capability to port, not an OS exception.
